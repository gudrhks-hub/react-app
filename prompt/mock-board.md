# Mock Board 개발 기획 문서

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | `mock-board` |
| 서비스명 | Mock Board |
| 목적 | 로그인 후 게시판(글 등록/수정/삭제)과 회원정보(회원 목록/등록/수정/삭제)를 관리하는 웹 페이지 |
| 서버 | 없음. 모든 데이터는 mock 데이터를 사용하되, **axios로 서버와 통신하는 형태**로 구현 |
| 디자인 방향 | 모던하고 심플한 관리자 UI |

## 2. 기술 스택 및 기본 구성 (CLAUDE.md 기준)

| 구분 | 내용 |
| --- | --- |
| 빌드 도구 | Vite |
| 프레임워크/언어 | React + JavaScript (TypeScript 사용 안 함) |

## 3. 서버 통신 구조 (Mock)

```
화면(pages/comp) → service(authService, postService, memberService)
                → axios 인스턴스(api.js, baseURL=/api, 토큰 헤더 자동 첨부)
                → axios-mock-adapter (service/mock/server.js) ── 가로챔
                → mock DB (localStorage, 최초 실행 시 seed 데이터로 초기화)
```

- 화면과 service 코드는 실제 서버와 통신하는 코드와 동일하다.
- **실제 서버가 생기면 `main.jsx`의 mock 설치 한 줄만 제거**하고 `baseURL`만 바꾸면 된다.
- 모든 mock 응답에 **300ms 지연**을 주어 실제 통신처럼 로딩 상태가 보이게 한다.
- 로그인 시 mock 토큰을 발급하고, 이후 요청은 `Authorization: Bearer {token}` 헤더로 보낸다.
  - 토큰이 없거나 잘못되면 mock 서버가 `401`을 반환 → 자동 로그아웃 후 로그인 화면으로 이동.
  - 권한이 없는 요청은 `403`을 반환한다.
- 응답 데이터에는 **비밀번호를 절대 포함하지 않는다.**

### 3.1 API 명세

| 기능 | Method | URL | 권한 | 응답 |
| --- | --- | --- | --- | --- |
| 로그인 | POST | `/api/auth/login` | 없음 | `{ token, user }` / 실패 401 |
| 내 정보 | GET | `/api/auth/me` | 로그인 | `user` |
| 게시글 목록 | GET | `/api/posts` | 없음 (비로그인 가능) | `post[]` (최신순) |
| 게시글 상세 | GET | `/api/posts/:id` | 로그인 | `post` (조회 수 +1, 수정 화면은 `?increaseView=false`로 조회 수 증가 없음) |
| 게시글 등록 | POST | `/api/posts` | 로그인 | `post` |
| 게시글 수정 | PUT | `/api/posts/:id` | 본인 또는 운영자 | `post` / 403 |
| 게시글 삭제 | DELETE | `/api/posts/:id` | 본인 또는 운영자 | 204 / 403 |
| 회원 목록 | GET | `/api/members` | 로그인 | `member[]` |
| 회원 상세 | GET | `/api/members/:id` | 운영자 | `member` |
| 회원 등록 | POST | `/api/members` | 운영자 | `member` / 아이디 중복 409 |
| 회원 수정 | PUT | `/api/members/:id` | 운영자 | `member` |
| 회원 삭제 | DELETE | `/api/members/:id` | 운영자 (본인 삭제 불가) | 204 / 400 |

## 4. 데이터 구조

### 4.1 회원 (member)

| 필드 | 설명 | 예시 |
| --- | --- | --- |
| `id` | 회원 번호 (자동 증가) | `1` |
| `username` | 아이디 (중복 불가, 수정 불가) | `admin` |
| `password` | 비밀번호 (mock DB에만 저장, 응답 제외) | `admin1234` |
| `name` | 이름 | `관리자` |
| `role` | 권한 `ADMIN`(운영자) / `USER`(사용자) | `ADMIN` |
| `createdAt` | 가입일 (ISO 문자열) | `2026-10-01T09:00:00.000Z` |

### 4.2 게시글 (post)

| 필드 | 설명 |
| --- | --- |
| `id` | 글 번호 (자동 증가) |
| `title` | 제목 |
| `content` | 내용 |
| `views` | 조회 수 (상세 조회 시 +1) |
| `authorId` | 글쓴이 회원 번호 |
| `authorName` | 글쓴이 이름 (응답 시 회원 정보에서 채움, 삭제된 회원이면 `(탈퇴회원)`) |
| `createdAt` | 등록일 |
| `updatedAt` | 수정일 (수정 전에는 `null`) |

### 4.3 Seed 데이터 (최초 실행 시)

| 아이디 | 비밀번호 | 이름 | 권한 |
| --- | --- | --- | --- |
| `admin` | `admin1234` | 관리자 | 운영자 |
| `user1` | `user1234` | 홍길동 | 사용자 |
| `user2` | `user1234` | 김철수 | 사용자 |

- 게시글 5건 내외를 샘플로 등록해 둔다.
- 로그인 화면 하단에 테스트 계정 안내를 표시한다.

## 5. 기능 요구사항

### 5.1 로그인
- 아이디, 비밀번호 입력 후 `로그인` 버튼(또는 Enter)으로 로그인한다.
- 빈 값이면 요청하지 않고 안내 메시지 표시.
- 실패 시 `아이디 또는 비밀번호가 올바르지 않습니다.` 표시.
- 성공 시 로그인 전에 가려던 화면으로 이동한다. (없으면 게시판 목록)
- 로그인 정보(토큰, 사용자)는 localStorage에 유지 → 새로고침해도 로그인 유지.
- 로그인하지 않은 상태로 **게시판 목록 외의 화면**에 접근하면 로그인 화면으로 이동.

### 5.2 공통 레이아웃
- **첫 화면은 게시판 목록**이며, 로그인하지 않아도 볼 수 있다.
- 상단 헤더: 서비스명 / 메뉴(`게시판`, `회원정보`) / 오른쪽 끝 영역
  - 비로그인 상태: 오른쪽 끝에 `로그인` 버튼
  - 로그인 상태: 오른쪽 끝에 **회원 아이콘 + 이름 + 권한 배지**
- `회원정보`는 로그인해야 볼 수 있다. 메뉴는 비로그인 상태에도 보이며, 누르면 로그인 화면으로 이동한다.
- 현재 메뉴는 강조 표시.

#### 회원 드롭다운 (로그인 상태)
- 회원 아이콘 또는 이름을 클릭하면 드롭다운이 열린다. (다시 클릭하면 닫힘)
- 드롭다운 항목

| 항목 | 동작 |
| --- | --- |
| 회원정보 | 회원 목록 화면(`/members`)으로 이동 |
| 로그아웃 | 로그아웃 후 로그인 화면으로 이동 |

- 항목을 선택하거나, 드롭다운 바깥을 클릭하거나, `Esc`를 누르면 닫힌다.

### 5.3 게시판
| 화면 | 내용 |
| --- | --- |
| 목록 | 번호, 제목, 글쓴이, 조회 수, 등록일 표시 (최신순). `글쓰기` 버튼 |
| 상세 | 제목, 글쓴이, 등록일, 수정일, 조회 수, 내용. `목록` / (권한 있으면) `수정` `삭제` |
| 등록 | 제목, 내용 입력 (둘 다 필수). `등록` / `취소` |
| 수정 | 등록 화면과 같은 폼에 기존 값 채움. `저장` / `취소` |

| 구분 | 목록 | 상세 | 등록 | 수정/삭제 |
| --- | --- | --- | --- | --- |
| 비로그인 | O | X (제목 클릭 시 로그인 화면) | X (`글쓰기` 버튼 숨김) | X |
| 사용자 | O | O | O | **본인 글만** (다른 사람 글은 보기만) |
| 운영자 | O | O | O | 모든 글 |

- 게시글 등록/수정/삭제는 **로그인해야 가능**하다. (화면과 mock 서버 양쪽에서 체크)
- 삭제 전 확인 창(`삭제하시겠습니까?`).
- 날짜 표시 형식: `yyyy-MM-dd HH:mm`, 수정일이 없으면 `-`.

### 5.4 회원정보
| 화면 | 운영자 | 사용자 | 비로그인 |
| --- | --- | --- | --- |
| 회원 목록 (번호, 아이디, 이름, 권한, 가입일) | O | O (**읽기만**) | X (로그인 화면) |
| 회원 등록 버튼 / 등록 화면 | O | X | X |
| 수정 / 삭제 버튼 | O | X | X |

- 회원 등록/수정/삭제는 **운영자만** 가능하다.

- 회원 등록: 아이디, 비밀번호, 이름, 권한(운영자/사용자 선택) — 모두 필수, 아이디 중복 시 안내.
- 회원 수정: 아이디는 수정 불가. 이름, 권한, 비밀번호(빈칸이면 기존 유지) 수정.
- 회원 삭제: 확인 창 후 삭제. **로그인한 본인은 삭제 불가.**
- 사용자가 등록/수정 URL로 직접 접근하면 `권한이 없습니다.` 안내 후 목록으로 이동.
- 운영자가 자기 정보를 수정하면 헤더의 이름/권한도 갱신한다.

### 5.5 공통 처리
- 요청 중에는 로딩 표시, 버튼 중복 클릭 방지.
- 에러 응답의 `message`를 화면에 표시.

## 8. Store 설계 (authStore)

## 10. 개발 순서

1. Vite 프로젝트 생성, Tailwind / oxlint / vite.config / StrictMode 제거
2. 라이브러리 설치: react-router-dom, zustand, axios, axios-mock-adapter
3. mock DB(seed, db) + mock 서버(server.js) + axios 인스턴스
4. service (auth, post, member) + authStore
5. 로그인 화면, 레이아웃, 라우트 가드
6. 게시판 (목록/상세/등록/수정/삭제)
7. 회원정보 (목록/등록/수정/삭제, 권한 처리)
8. lint / build 확인, 브라우저에서 기능 검증
